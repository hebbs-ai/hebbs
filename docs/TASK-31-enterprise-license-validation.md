# TASK-31: Enterprise License Key Validation

## Problem

GHCR tokens are just passwords. A customer can pull our Docker images and deploy on unlimited machines. We have no visibility into how many deployments exist, no way to enforce seat limits, and no way to revoke access per-deployment.

## Solution

Add license key validation to the platform. On startup, the platform calls our license server. If the key is invalid or expired, the platform refuses to start.

## How it works

```
Customer's machine                         Our infrastructure
+---------------------------+              +------------------------+
|  hebbs-platform            |   startup   |  license.hebbs.ai      |
|                           | ----------> |                        |
|  HEBBS_LICENSE_KEY=hb_lic_|  POST /v1/  |  Validate key          |
|  abc123...                |  validate   |  Check: active, seats, |
|                           | <---------- |  expiry, features      |
|  Valid? Start.            |   200 OK    |                        |
|  Invalid? Exit.           |   or 403    |  Log deployment        |
+---------------------------+              +------------------------+
```

## License key format

```
hb_lic_<customer-slug>_<random>
e.g. hb_lic_acme_corp_a8f3b2c1d4e5
```

## License server API

```
POST https://license.hebbs.ai/v1/validate
{
  "license_key": "hb_lic_acme_corp_a8f3b2c1d4e5",
  "deployment_id": "<auto-generated-uuid>",
  "version": "0.4.0",
  "workspaces": 3,
  "memories": 12450
}

Response 200:
{
  "valid": true,
  "customer": "Acme Corp",
  "plan": "enterprise",
  "max_workspaces": 10,
  "max_memories": 1000000,
  "expires_at": "2027-03-30T00:00:00Z",
  "features": ["tune", "multi-workspace", "team-management"]
}

Response 403:
{
  "valid": false,
  "reason": "expired" | "revoked" | "seat_limit" | "invalid"
}
```

## Platform changes

In `hebbs-platform/src/index.ts`, before starting the server:

```typescript
// Validate license on startup
const licenseKey = process.env.HEBBS_LICENSE_KEY;
if (licenseKey) {
  const resp = await fetch("https://license.hebbs.ai/v1/validate", {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({ license_key: licenseKey, version: "0.4.0" }),
  });
  if (!resp.ok) {
    console.error("License validation failed. Contact support@hebbs.ai");
    process.exit(1);
  }
}
```

## What we can see

Per deployment:
- Customer name
- Deployment UUID (auto-generated on first start, persisted)
- Version running
- Workspace count
- Memory count
- Last validation time
- IP address (from the request)

Across all customers:
- Total deployments
- Who is active (validated in last 24h)
- Who is outdated (old version)
- Who is approaching limits

## Enforcement levels

| Level | Behavior |
|-------|----------|
| **Soft** | Log warning if validation fails, but keep running. For early customers on trust. |
| **Hard** | Refuse to start if validation fails. For paid contracts. |
| **Metered** | Allow startup, but disable features (e.g., no new workspaces) if over limit. |

Start with soft for the first customer. Move to hard once license server is production-ready.

## License server

Simple Node.js or Python service. SQLite or Postgres for license records. Deploy on our infrastructure (Vercel, Railway, or the same AWS machine).

Separate task to build the license server itself.
